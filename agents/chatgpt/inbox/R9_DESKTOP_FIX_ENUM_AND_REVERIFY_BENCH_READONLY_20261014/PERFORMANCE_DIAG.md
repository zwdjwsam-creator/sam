# 速度诊断

1639 的复制耗时是事实：5032 个实体、1073739240 字节、1401.47 秒，约 0.766 MB/s（10^6）或 0.731 MiB/s（2^20）。验收后来补上，不改写这个复制计时，也不把它变成全量 ETA。`bench_measured` 仍以程序原字段 false 为准。

## 代码里的每实体成本

- 源读取块是 1MiB。
- 临时目标校验用 `min(1024, remaining)` 把整文件再读一遍，1GiB 大约是一百万次读。
- 每个实体 `FlushFileBuffers` 一次。
- 目录、实体 INTENT、实体 DONE、每个别名都各自 `commit`。
- 源端每次还有打开和复制前后的 identity。

## 八个文件的只读探针

每个源最多读前 64KiB，八个源合计 524288 字节。没有建测试文件，没有 flush，没有写。

| 步骤 | 源 UNC 中位 | 本地目标中位 |
| --- | ---: | ---: |
| open | 0.105 秒 | 0.0036 秒 |
| identity | 0.021 秒 | 0.000032 秒 |
| 读 64KiB | 0.00018 秒 | 0.000036 秒 |

打开和 identity 的差距比这 64KiB 本身大。样本只有 8 个，而且第一次打开可能含连接建立，不能当成所有 5032 个文件的平均值。

如果以后要优化，应仍走同一执行器，优先减少每实体的整文件 1KiB 复读、flush 和状态提交次数，并用同一次测量核对。本轮没有改这些复制行为。
