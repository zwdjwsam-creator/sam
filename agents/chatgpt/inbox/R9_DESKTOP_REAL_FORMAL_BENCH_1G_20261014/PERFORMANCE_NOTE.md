# 速度说明

这次只有一次 execute，退出码 4，验收没有通过。程序输出里的 `bench_measured` 仍是 false。本说明不把它改成 true，也不把下面的速率当成正式迁移时间。

## 实测

启动者墙钟 1426.64 秒，含一次 6GB 源计划 SHA。runner 内部总时间 1422.05 秒，这段从计划摘要核对之后开始，不要把那次 6GB 读取按每 1GiB 复制再乘一遍。

- 目录 754 个，1.287 秒
- 实体复制 5032 个，唯一字节 1073739240，1401.47 秒
- 复制速率 0.766 MB/s（除以 10^6）和 0.731 MiB/s（除以 2^20）
- 实体平均 213382 字节
- 别名 7 个，0.023 秒
- 链接 108 个，0.381 秒
- 验收函数 1.787 秒，但 `content_hash_calls=0`，验收读到的内容字节和分配字节都是 0
- 峰值工作集 37601280 字节

链路仍是到 192.168.100.2 的 2.5 Gbps。2.5 Gbps 不是 2.5 GB/s。理论上限约 312.5 MB/s。这次小文件复制大约 0.77 MB/s，远低于链路上限。

## 为什么不能外推小时数

冻结计划口径仍是 365007198749 内容字节、1223721 实体、8715067 文件路径、233660 目录、4825 链接。这次只有 7 个别名，不能用来估计全量别名时间。验收没有真正哈希，所以验收成本也没有测到。源在计划冻结之后有没有变化，这次没有重扫。把 0.766 MB/s 线性乘到全量字节上，只是一个未确认条件的算术，不是开工时间。
